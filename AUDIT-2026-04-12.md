## 2. Failing Test

### F1 — `wacp-tools::execution::tests::pre_cancelled_token_returns_cancelled_immediately`

**Crate:** `wacp-tools`
**File:** `crates/wacp-tools/src/execution.rs:539`
**Introduced:** pre-Stream-A (Phase 20 era)
**CI impact:** blocks `cargo test --workspace`

**Symptom.** Test cancels a `CancellationToken` before calling `execute()`, then expects `Err(Cancelled)`. Instead gets `Ok({"value": 1})` — the handler completes before the cancellation branch fires.

**Root cause.** `invoke_with_timeout` (line 103) uses `tokio::select!` with three branches:

```rust
tokio::select! {
    result = handler_future => result,            // branch 1
    () = tokio::time::sleep(duration) => { ... }  // branch 2
    () = cancel.cancelled() => { ... }            // branch 3
}
```

When the token is already cancelled, branch 3 is immediately ready — but `tokio::select!` polls branches in declaration order. The echo handler (branch 1) also completes immediately, so it wins the race non-deterministically on most runs.

**Fix.** Add an early-return check before the `select!`:

```rust
async fn invoke_with_timeout( ... ) -> Result<serde_json::Value, ToolError> {
    if cancel.is_cancelled() {
        return Err(ToolError::cancelled());
    }
    // ... existing select! logic
}
```

Single-line change at `execution.rs:110`. No behavioral change for non-cancelled tokens.
