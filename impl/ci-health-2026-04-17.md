## 2. Three root causes

### 2.1 Console Rust integration job — mold linker missing on runner image

`CI — console > Integration — console + real wacp-runtime (W7)` fails during `cargo build`:

```
error: linking with `clang` failed: exit status: 1
  = note: clang: error: invalid linker name in argument '-fuse-ld=mold'
error: could not compile `quote` (build script) due to 1 previous error
error: could not compile `proc-macro2` (build script) due to 1 previous error
##[error]Process completed with exit code 101.
```

Root cause: a repo-level Cargo configuration (likely `.cargo/config.toml`, check the workspace root) passes `-C link-arg=-fuse-ld=mold` to rustc, but the `ubuntu-latest` GitHub Actions runner image doesn't ship `mold`. The failure fires inside build scripts (`proc-macro2`, `quote`) — i.e., during the first cargo compile that tries to link a native artefact.

Fix options:

1. `rui314/setup-mold@v1` action inserted into every Rust-running job before `cargo build` / `cargo test`. Cleanest and matches local-dev expectations. The three workflows that compile Rust are `ci-wacp.yml`, `ci-console.yml`, `coverage.yml`.
2. `sudo apt-get install -y mold` inline step. Works but messier.
3. Remove the `-fuse-ld=mold` hint from the repo cargo config and keep it as an opt-in developer convenience via `~/.cargo/config.toml` or `CARGO_*` env vars. Most portable; forfeits the CI link-speed gain.

Recommend option 1.

### 2.2 Frontend lint job — fails before typecheck / test / build

`CI — console > Frontend — lint, typecheck, test, build` fails at the **Lint** step. Downstream Typecheck / Test / Build steps never run, so the current red status mask whatever state those would be in.

Evidence: the run view shows step state `X Lint / - Typecheck / - Test / - Build` — `-` means "not executed" in `gh run view`.

I didn't capture the specific lint errors during D1 (they weren't on the critical path for the smoke-test). Reproducible locally as `cd wacp-console/frontend && pnpm lint`. Expect overlap with §2.3's strict-mode drift — the same patterns that fail `tsc` tend to fire `@typescript-eslint` rules too.

### 2.3 `pnpm build` — 55 pre-existing `tsc` errors in test files

`pnpm build` = `tsc -b && vite build`. `tsc -b` fails with 55 errors, **all** in `src/**/*.test.ts(x)` and `src/**/test-helpers.tsx`. Evidence: `pnpm build 2>&1 | grep -c "error TS"` on `dev` post-D1 = 55. Representative shapes:

- ~30+ × `TS2345: Argument of type 'HTMLElement | undefined' is not assignable to parameter of type 'Document | Node | Element | Window'` — `noUncheckedIndexedAccess` strictness on array indexing (`rows[0]` returns `HTMLElement | undefined`, passed into a function taking `Element`).
- `TS2532: Object is possibly 'undefined'` — same pattern on hook-return destructuring.
- `TS6133: 'data' is declared but its value is never read` in `ProfilesPage.test-helpers.tsx:54` — unused-param drift.
- Misc `TS2345` on `UseMutationResult` generic arguments in `src/api/hooks/index.test.ts` (~839, ~875, ~912) — tests pass a void-arg mutation where the helper expects `Record<string, unknown>`.

Root cause: `tsconfig.json` has `"include": ["src"]`, which pulls every test file into `tsc -b`. With `strict: true` + `noUncheckedIndexedAccess: true`, the F-series tests landed during §13.7.1–§13.7.4 (`fe48c7b`, `e870018`, `92b3ddb`, `543c295`) included code patterns that fail strict checks.

Why this wasn't caught at author-time:
- Lint failure (§2.2) prevents the CI `Typecheck` + `Build` steps from running, so the tsc errors never appear in the red-run output.
- Local F-series workflow likely used `pnpm vitest run` (esbuild-based) and skipped `tsc` end to end.

Fix options:

1. **`tsconfig.build.json` excluding test globs.** Point `"build"` script at the new tsconfig. Keeps `pnpm typecheck` covering tests, keeps `pnpm build` fast + scoped to shipped code. 30–60 min.
2. **Fix the 55 errors.** Mechanical work — most are trivial non-null assertions (`row!` for `row`), unused-param renames, hook-generic narrowings. 1–2 h.
3. **Loosen `noUncheckedIndexedAccess` to `false` repo-wide.** Loses production-code benefit; not a fit.

Recommend option 1 for the immediate unblock (cheap, sound), then option 2 in a follow-up so `pnpm typecheck` also returns green.

### 2.4 `cargo fmt --check` drift (observed, side-issue)

`cargo fmt --all --check` reports pre-existing drift in at least:

- `wacp/crates/wacp-clock/src/tests.rs:404`, `:537` — long-line `assert!` / `assert_eq!` not broken.
- `wacp-console/crates/console-test-support/src/mock_grpc.rs:177` — struct literal not split across lines.

Probably more scattered through the workspace. `ci-lint.yml` normally runs `cargo fmt --check` and would fail on these; the fact that the lint workflow is itself red (see §1) for 4 cycles running means whatever it's failing on may mask this. One `cargo fmt --all` + commit cleans it up once the main CI blockers are gone.

## 3. Impact on §13.7.7 D3

D3 adds a Playwright stage to `ci-console.yml`:

```
cargo build -p wacp-console
cargo build -p console-test-support --bin wacp-mock-runtime
pnpm install --frozen-lockfile
pnpm build
pnpm exec playwright test
```

With today's state:
- `cargo build` breaks at mold-link (§2.1).
- `pnpm build` breaks at `tsc` (§2.3).
- If the Playwright job shares the Frontend job's lint gate, it also breaks at `pnpm lint` (§2.2).

**D3 cannot land green until at least §2.1 and §2.3 resolve.** §2.2 is adjacent; if it shares a strict-mode-drift root cause with §2.3, a single fix pass on the test-file hygiene covers both.

Implication for §13.7.7 sequencing: the cleanup commit lands between D2 and D3, not inside D3. D3's scope stays on "add Playwright stage + wire Codecov", not "add Playwright stage + fix everyone's prior CI regressions."

## 4. Recommended fix order

1. **§2.3 — `tsconfig.build.json` split.** Unblocks `pnpm build` locally and in CI. 30–60 min.
2. **§2.1 — `rui314/setup-mold@v1`.** Add to the three Rust jobs across `ci-wacp.yml`, `ci-console.yml`, `coverage.yml`. 15 min.
3. **§2.2 — `pnpm lint` drifts.** After §2.3 lands, rerun `pnpm lint` locally and address any remaining rules. Likely small once strict-mode drift is out of the test files. 30 min worst case.
4. **§2.4 — `cargo fmt --all`.** One commit, no diff beyond whitespace. 5 min.
5. **Verify.** Push to a scratch branch, confirm all five workflows go green on that branch. Only then unblock §13.7.7 D3.
